# デッキを作る

40枚のデッキを1本作ります。デッキは**このゲームで実際に遊ぶ単位**なので、カード単体の面白さよりも、**40枚がひとつの勝ち筋に向かって噛み合っているか**を優先します。

## ファイル構成

デッキは**1フォルダ**で、カードは**1枚1ファイル**。

```
デッキ/<デッキ名>/
├─ overview.md          デッキ全体（勝ち筋・カード一覧・回し方・見た目の共通ルール）
└─ カード一覧/
   ├─ 00_<リーダー名>.md
   ├─ 01_<カード名>.md   コストの安い順に番号を振る
   └─ …
```

**カードのmdには絵の指定（外見・情景・背景）も書く。**そこに書いた日本語が、そのまま
`generating-card-art` スキルで画像APIへ送られる。

## 各種ステップ

以下のチェックリストを応答にコピーし、完了したステップにチェックを入れながら進める。

```
デッキ作成の進捗:
- [ ] Step1. ルールと既存デッキの理解
- [ ] Step2. デッキコンセプトの決定
- [ ] Step3. 枠配分とカードのドラフト
- [ ] Step4. 見た目の共通ルールを決める
- [ ] Step5. ファイルの作成
- [ ] Step6. 最終チェック
```

## Step1. ルールと既存デッキの理解

必ず読む。記憶や推測で書かない。

- **基本数値**：`ルール/README.md` — 40枚、同名3枚、HP25、場6体、コスト上限10
- **カード表記**：`ルール/03_カードとキャラクター.md` — キャラクター／スペル／武器の書き方
- **キーワード**：`ルール/06_キーワード能力.md` — 使える能力の全部。**ここに無い能力はユーザーと相談して決めること**
- **用語**：`ルール/08_用語集.md` — 効果文に使う語と、表記ゆれの統一
- **既存デッキ**：`デッキ/*/overview.md` — このリポジトリに入ってるデッキ全て
- **絵の全体ルール**：`イラスト/共通ルール.md` — 絵柄・構図・描かせないもの。**全デッキ共通なのでデッキ側に書き写さない**

既存デッキは**立ち位置と固有キーワードが被っていないかを見るために読む**。
カードの作り方や数値をそこから写さない。数値の根拠は `manual/` を使う。

設計の基準はスキル内の `manual/` にある。Step3に入る前に読む。

| ファイル | 内容 |
|---|---|
| `manual/デッキ構成.md` | マナカーブ、枚数の確率、役割ごとの枠 |
| `manual/カード設計.md` | 素点の目安、スペルのコスト、固有キーワード、効果文の書き方 |

## Step2. デッキコンセプトの決定

以下の項目をユーザーからヒアリングする。まだデッキを作成しない。

| 項目 | 内容 |
|---|---|
| **アーキタイプ** | どの速度で勝つか |
| **デッキの方向性** | どういうデッキにするか。どのような形で戦うのか |
| **勝ち筋** | 何ターン目に、何をして勝つか |
| **負け筋** | 何をされると負けるか |
| **仕掛け** | このデッキだけが持つ仕組みがあるか |

### アーキタイプ

| 型 | 勝つターン | 主な勝ち筋 |
|---|---|---|
| **アグロ** | 6〜8 | 序盤から攻めて早期ターンの決着を目指す |
| **ミッドレンジ** | 8〜10 | 中コストで盤面を取り続け、大型で〆る |
| **コントロール** | 12〜 | 除去とドローで捌き、相手の息切れを待つ |
| **ランプ** | 9〜11 | 最大MPを伸ばし、本来より早く大型を出す |
| **コンボ** | 固定 | 特定の組み合わせが揃った瞬間に勝つ |

上の5つに収まらない型を作ってもよい。その場合は**勝つターンと勝ち筋を自分で定義してから**進める。

### 負け筋を必ず立てる

全アーキタイプに勝てるデッキを作らない。**弱点が無いデッキは、対戦相手を面白くなくする。**

負け筋は、勝ち筋の裏返しから作る。速さを買ったなら長期戦に弱い。大型を買ったなら序盤が空く。
「対策カードを引かれると負ける」は負け筋ではない。**そのデッキが構造的に持っている穴**を書く。

## Step3. 枠配分とカードのドラフト

40枚をいきなり書かない。**先に枠を配り、後から名前を入れる。**

### 手順

`manual/` を開きながら、上から順に確定させる。

| # | やること | 参照 |
|---|---|---|
| 1 | マナカーブを決める | `manual/デッキ構成.md` — マナカーブ／枚数は確率で決める |
| 2 | 役割の枠を配る | `manual/デッキ構成.md` — 役割の枠 |
| 3 | 固有キーワードを定義する | `manual/カード設計.md` — デッキ固有キーワード |
| 4 | カードを1枚ずつ埋める | `manual/カード設計.md` — 素点の目安／スペルのコスト／効果文の書き方 |
| 5 | 噛み合いを確かめる | 下の「噛み合っているかの確かめ方」 |

- 仕掛けの無いデッキなら3は飛ばす
- **各段階でユーザーと壁打ちする。ユーザーが納得するまで次へ進まない**
- ファイルへの出力はStep5まで行わない

### 噛み合っているかの確かめ方

ドラフトの段階で必ず通す。最も多い失敗。

- **悪い例**：ドローが強いカードを入れたので、アグロなのに8コストのドロー2を採用した
  → 勝つターンに間に合わない。強いカードではなく、**勝ち筋に乗るカード**を入れる
- **良い例**：アグロなので、ドローの代わりに1コスト1ダメージを採用した
  → 序盤は盤面、終盤は顔。どちらのターンでも腐らない

**全部のカードが、Step2で書いた勝ち筋に接続していること。**

## Step4. 見た目の共通ルールを決める

カードの絵を書く前に、**デッキ全体で揃える約束を3〜4項目**決める。
これが無いと、40枚が別のゲームのカードに見える。

`バックエンドストーリー/` の設定から起こす。**推測で世界観を足さない。**

決めるのは4つ。

| 項目 | 決めること | 例 |
|---|---|---|
| **光源と配色** | 何が画面を照らすか。基調色と差し色 | 光源は星光。深い藍と黒に、淡い金と冷たい菫色 |
| **力の見た目** | このクラスの魔法がどう見えるか | 力が働くところに淡い星座の記号が出る。魔法陣は使わない |
| **明暗の振り分け** | どのカードが明るく、どれが暗いか | 物語の前半は明るい星夜、闇落ち後は暗くよどむ |
| **人物の描き分け** | この町の人間に共通する特徴 | オルレアの人間は黒髪と琥珀色の瞳 |

**明暗の振り分けは必ず入れる。**これが無いと40枚が同じ色の泥になる。
振り分けの軸は物語（前半／後半）でもコスト帯でもよいが、**どのカードがどちらかを決められる軸**にする。

**絵柄・構図・描かせないものは書かない。**それは `イラスト/共通ルール.md` にあり、全デッキ共通。

## Step5. ファイルの作成

### 置き場所とテンプレート

| 作るもの | 置き場所 | テンプレート |
|---|---|---|
| デッキ全体 | `デッキ/<アーキタイプ名リーダー名>/overview.md` | `template/overview.md` |
| カード1枚 | `デッキ/<デッキ名>/カード一覧/<2桁番号>_<カード名>.md` | `template/card.md` |

- 番号は**コストの安い順**に `01` から振る。`00` はリーダー
- ファイル名の番号と `overview.md` のカード一覧の `#` を揃える

### 書き方のルール

**overview.md**

- 見出しはデッキ名だけ。フォルダ名と揃える
- 冒頭の表に リーダー／クラス／アーキタイプ／舞台／合計枚数
- 勝ち筋・負け筋・とどめは箇条書きで1行ずつ
- **デッキ固有能力だけを書く。** 守護・突進などの共通キーワードは書かない（`ルール/06` にある）
- カード一覧はコストの安い順。スペルの攻/HPは `─`
- 末尾に Step4 で決めた「見た目の共通ルール」

**カード1枚**

- 項目は表で書く。**種類ごとに行を増減する**
  - キャラクター：クラス／種類／コスト／攻撃力／HP／投入枚数（＋種族タグ）
  - スペル：クラス／種類／コスト／投入枚数
  - 武器：クラス／種類／コスト／攻撃力／耐久力／投入枚数
  - リーダー：クラス／種類／HP
- 効果が無いなら `効果なし` と書く。節ごと消さない
- 効果が複数あるなら箇条書きで**1行1効果**
- 数字は半角に統一する
- **`## 絵` の 外見／情景／背景 を必ず埋める**

### 絵の書き方

この3つを繋いだ日本語が、そのまま画像APIへ送られる。**英語は書かない。**

| 節 | 書くこと | 書かないこと |
|---|---|---|
| **外見** | 年齢・性別 → 髪 → 瞳 → 服装 → 雰囲気の一文 | 物語の経緯 |
| **情景** | このカードで何をしているか。1〜3文 | 「〜したい関係上」などの判断の説明 |
| **背景** | 明暗と空気だけ | 物語の説明 |

守ること。

- **同じ町の人間は髪と瞳を揃える。** 並べたとき同じ土地の人間に見える
- **複数のカードに出る人物は、同じ特徴を書く。** 書き分けると別人の絵になる
- **人でないものは「人ではない」と明記する。** 獣・機構・魔族・現象は、書かないと人型で出る
- **大きさを書く。** 「小さな」と書くと画面が余白だらけになる。「人の3倍」のように基準を示す
- **接地と視線を書く。** 「立っている」だけだと乗っている感が出ない
- **否定文を避ける。** 「星を読む道具は持たない」は、その文字が絵に描き込まれた実例がある。「手には何も持たない」と肯定で書く

## Step6. 最終チェック

書き終わったら、全項目を通す。

### 構築チェック

- [ ] **合計40枚ちょうど** — 投入枚数を実際に足し算して確かめた
- [ ] **同名カードが3枚以下**
- [ ] **クラスが混ざっていない** — リーダーのクラスと共通のみ
- [ ] **1〜3コストが12枚以上**
- [ ] **フィニッシャーが4枚以上**
- [ ] **コストが10以下**、**場に出るキャラクターが6体上限を前提にしている**

### ファイル構成チェック

- [ ] `デッキ/<デッキ名>/overview.md` と `カード一覧/` がある
- [ ] **カードの枚数ぶんファイルがある**（リーダー含めて15前後）
- [ ] ファイル名の番号がコストの安い順に振られていて、`00` がリーダー
- [ ] `overview.md` のカード一覧のリンクが全部そのファイルに繋がっている
- [ ] 読み込めることを確認した：`node .claude/skills/generating-card-art/art/list.js <デッキ名>`

### 品質チェック

- [ ] **勝ち筋が1行で言える**
- [ ] **負け筋が書かれている**
- [ ] **負け筋が枠配分と一致している** — 削った役割が、そのまま負け筋になっている
- [ ] **回し方が埋まっている** — 序盤／中盤／終盤・仕掛け・有利不利
- [ ] **全カードが勝ち筋に接続している** — 「強いから入れた」枠が無い
- [ ] **既存デッキと立ち位置が被っていない** — 速度か仕掛けのどちらかが違う
- [ ] **固有キーワードが1語で、定義と例文があり、6枚以上に乗っている**
- [ ] **既存キーワードで書けるものを新設していない**
- [ ] **素点が目安から外れる箇所に理由がある**
- [ ] **顔へのバーン総量が15前後に収まっている**
- [ ] **表記が `ルール/08_用語集.md` に揃っている**

### 絵のチェック

- [ ] **全カードの 外見／情景／背景 が埋まっている**
- [ ] **見た目の共通ルールに明暗の振り分けがある** — 全カードが同じ暗さになっていない
- [ ] **同じ町の人間の髪と瞳が揃っている**
- [ ] **複数カードに出る人物の特徴が一致している**
- [ ] **人でないものに「人ではない」と書いてある**
- [ ] **英語を書いていない**

### 他ファイルとの整合

- [ ] デッキ固有キーワードを作ったなら、`ルール/06_キーワード能力.md` の「デッキ固有キーワード」表に追記した
- [ ] 新しいリーダーなら、`ルール/05_テンション.md` のテンションスキル表に追記した
- [ ] 新しいクラスなら、`カードフレーム/frame.json` の `frames` にクラス名と枠画像を追加した
- [ ] ルールに無い挙動が必要になったなら、`ルール/09_未確定事項.md` の保留中に書いた
- [ ] 他デッキのファイルを書き換えていない

### 仕上げ

- [ ] テンプレートの `<!-- -->` コメント行を全て削除した

すべてにチェックがついたら完了。1つでも漏れたらStep3に戻る。

### 対戦での検証（任意）

`simulating-deck-matchups` スキルで、既存デッキとの勝率を数字で測れる。
勝率が**35〜65%の外**に出たら、Step3の枠配分に戻る。

### 絵の生成（任意）

`generating-card-art` スキルで、カードmdの 外見／情景／背景 から画像を生成できる。

## 注意事項

このスキルでやってほしくないこと。

- **ルールを読まずに書き始めない。** Step1の資料を推測で代用しない
- **勝ち筋を決める前にカードを書かない**
- **弱点の無いデッキを作らない。** 負け筋を必ず1つ持たせる
- **強いカードを理由に採用しない。** 勝ち筋に乗るかだけで決める
- **既存デッキを写さない。** 立ち位置とキーワードの重複を見るために読むのであって、数値やカードの作り方の手本にしない
- **枚数を感覚で決めない。** `manual/デッキ構成.md` の確率表で裏を取る
- **`manual/` を読まずに数値を決めない。** 素点も枚数も、記憶で書かない
- **既存キーワードで書けるものを新設しない。** 仕掛けは1語にまとめる
- **ランダム効果を作らない。** レアリティ・進化・配置も採用しない
- **他デッキの既存カードを、新デッキの都合で書き換えない**
- **表記を `ルール/08_用語集.md` から外さない**
- **40枚を数えずに完成としない。** 目分量で終わらせない
- **ルールを勝手に拡張しない。** 新しい挙動が要るなら `09_未確定事項.md` に書いて確認を取る
- **Step3でユーザーの合意を取らずにStep5へ進まない**
- **Step6を飛ばさない。** 構築チェックとファイル構成チェックを通さずに完了としない
- **カードのmdに英語を書かない。** 英訳はシステムが送信直前に行う
- **絵柄や構図をデッキ側に書かない。** それは `イラスト/共通ルール.md` にあり、全デッキ共通
- **1ファイルに全カードを詰め込まない。** カードは1枚1ファイル
- **ユーザーが書いた 外見／情景／背景 を、勝手に書き換えない**

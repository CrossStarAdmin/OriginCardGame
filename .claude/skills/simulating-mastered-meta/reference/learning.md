# 学習の仕組み

## 目次

- 全体の流れ
- 学習するもの（つまみ）
- 反省（1戦ごと）
- 試す・定着する
- 学習の相手
- 評価
- 停止の判定
- 公平さの約束
- 学習できないこと

---

## 全体の流れ

```
シーズン0：既定の打ち方で評価（学習前の基準）
シーズン1, 2, … ：
  各デッキ × 各対戦相手（ミラーは除く、4デッキなら12通り）について
    ① 対戦と反省  --reflect 戦。1戦ごとに悪手を拾う
    ② 直す案を出す  攻め方の両方向（2案）＋ パワーの使い方（1案）＋ 負けた試合で多く勝った試合で少ない悪手から --proposals-1 案 ＋ 反省に無い試しを1案以上
    ③ 試す  案ごとに --test 戦。今の打ち方と同じシード・同じ相手で比べる
    ④ 定着  採用基準を満たした案のうち、一番伸びた1案だけ
  全デッキの採用案をシーズンの最後にまとめて反映
  評価：評価専用のシードで総当たり --eval 戦、既定の相手への勝率 --gain 戦
```

**全デッキをシーズン開始時点の相手で学習し、最後にまとめて反映する。** 先に学習したデッキの変化を後のデッキが見られると、順番で有利不利が出るため。

---

## 学習するもの（つまみ）

`システム/対戦/knobs.js` の `SPEC` が全部。既定値と動かせる範囲もそこにある。

| 種類 | つまみ |
|---|---|
| マリガン | `mulliganKeepMax` |
| 攻め方 | `attackStyle`（aggro / midrange / control）、`raceMargin`、`aggroBigTradeThreat`、`midrangeTradeThreat`、`midrangeFaceGuardHp`、`controlFaceHp`、`burnKillThreat` |
| カードの評価 | `hasteValue` `rushValue` `tauntValue` `deathtouchValue`、カードごとの加減（`cards`） |
| 使う順番 | `costWeight` `followupWeight` `playThreshold` |
| パワー | `powerSlack`（溜める時機）、`chargeAtTwo`（パワー2でリーダー別の条件どおり急いで溜めるか）、`skillEarly`（スキルを手札より先に使うか）、`skillMinStage`（スキルを第何段階まで残すか） |

**学習は相手デッキ別（`vs`）の範囲にだけ書く。** 人が「vsアルベルは急ぐ」と打ち分けるのと同じ。デッキ共通（`base`）は既定値のまま。

## 反省（1戦ごと）

`reflect.js`。学習するデッキの手番ごとに、MPの残り・場・手札・パワー・パワースキルを使った段階を記録し、試合後に次を拾う。

| 見つけること | 条件 | 直す案 |
|---|---|---|
| MPの使い残し | 使えるカードがあるのにMPを残したターンが2回以上 | `playThreshold` −0.5、`costWeight` +0.1 |
| 序盤の空振り | 自分の最初の3ターン、場に何も残らなかった | `mulliganKeepMax` −1 |
| 終盤の軽い札余り | 両者合計16手番以降に、コスト2以下が手札に3枚以上 | `mulliganKeepMax` +1 |
| 削り切れず負け | 負けたとき相手リーダーのHPが5以下 | 攻め方を攻め寄りに、顔を狙う基準を上げる |
| 押し切られ | 負けたとき相手リーダーのHPが15以上 | 攻め方を守り寄りに、盤面を捌く基準を上げる、守護の評価+1 |
| 使わず抱えた札 | そのカードを使えるMPがあるのに2ターン以上手札に残し、試合が終わった | そのカードの評価 +1 |
| 低い段階のスキル | パワースキルを第1段階で2回以上使った | `skillMinStage` +1 |
| パワーの持ち越し | パワー3のまま手番を終えたことが2回以上 | `skillMinStage` −1、`skillEarly` を切り替える |
| スキル未使用 | 自分の手番が6回以上あってパワースキルを1回も使わなかった | `chargeAtTwo` を切り替える、`powerSlack` +0.5 |

**優先度は「負けた試合での発生率 − 勝った試合での発生率」。** 勝った試合でも同じくらい起きている悪手は、負けの原因ではないとみなして後回しにする。

「削り切れず負け」「押し切られ」で動かすつまみは、今の攻め方で効くものだけにする（aggro なら `raceMargin` など）。

**攻め方（`attackStyle`）は毎シーズン、全対面で両方向を試す。** 3択しかなく、一番勝率を動かすつまみのため。
最初の版はランダムな試しに任せていて、効く変更（+10pt級）を片方の学習だけが見つけ、2回の学習の最終対戦表が最大13pt食い違った。
動かせない向き（aggro をさらに攻め寄りにする等）のぶんは、反省に無い試しで埋めて、全デッキで試す数を揃える。

**パワーの使い方も毎シーズン、全対面で1案試す。** `chargeAtTwo` `skillEarly` `skillMinStage` `powerSlack` のどれかを1段動かす。

範囲の端で値が変わらない案（すでに1の `chargeAtTwo` を+1する等）は出さない。

**反省に無い試しを必ず1案入れる。** 反省のルールが拾えない改善を見逃さないため。人が「なんとなく違う打ち方を試す」ぶん。数値のつまみとカードの評価から選ぶ。

## 試す・定着する

`common.js` の `pairedTest`。**今の打ち方と案の打ち方を、同じシード・同じ相手の打ち方で戦わせる。**
デッキの並びが同じなので、運の差が打ち方の差に混ざりにくい。

採用基準（既定）：

- 勝率が +2pt 以上伸びた（`--minGain 0.02`）
- `z ≥ 2.5`（`--minZ 2.5`）。勝敗が分かれた試合だけを見て、偶然では出にくい差か

**z を 2.5 にしている理由：** 1シーズンに 12対面 × 7案 = 84回の検定をする。z ≥ 2 だと偶然の採用が1シーズンに1.9件ほど混ざるが、2.5 なら0.5件ほどに下がる。

1対面につき採用は1案まで。一度に大きく変えると、どの変化が効いたか分からなくなる。

---

## 学習の相手

- 基本は、相手デッキの**シーズン開始時点の打ち方**
- **4戦に1戦は、過去5シーズンのどれかの打ち方**（殿堂入り）。今の相手にだけ効く打ち方を覚えるのを防ぐ
- 反省と試すときで、同じ番号の試合は同じ相手の打ち方を使う

---

## 評価

`evaluate.js`。

- **評価専用のシード**（`EVAL_SEED_BASE`）で総当たり。学習のシードとは混ぜない。特定の試合展開を丸暗記した打ち方を、評価で見抜くため
- **既定の相手への平均勝率**：そのデッキだけ学習した打ち方にし、相手は既定の打ち方で戦ったときの平均。シーズン0との差が**上達幅**

---

## 停止の判定

次のどちらかで止まる。

- `--patience`（既定5）シーズン続けて、どの対面でも採用される案が無かった。試しの引きが悪いシーズンが続いただけで止まらないよう、少し粘る
- `--seasons`（既定30）に達した。**この場合は伸びが止まる前に打ち切っている**

**対戦表の変化が小さいことでは止めない。** 1シーズンに採用されるのは数件なので、学習の途中でも対戦表はほとんど動かない。
最初の版はこれで止めていて、採用基準の手前の案（z が 2 前後）が毎シーズン出続けているのに4シーズンで止まった。

---

## 公平さの約束

- 反省の戦数・試す案の数・採用基準は全デッキ同じ
- 学習できるつまみの種類は全デッキ同じ
- 対戦中に先読みの探索はしない。打ち方は評価の基準を変えるだけ
- 相手の手札やデッキの順番は見ない（反省も、AIの判断も、試合中に見える情報だけを使う）

---

## 学習できないこと

つまみに無い判断は、どれだけ回しても変わらない。結果を読むときの限界として報告に書く。

- **とどめの計算**（`ai.js` の `planLethal`）。見つけられる打点の種類は固定
- **リーダー別のパワーの細かい条件**（`chargePowerFirst` の「パワー2で急ぐ」条件の中身、`shouldUseSkill` のリーダー別の条件。例：アルベルの回復を使うHP）。条件を使うかどうか・スキルの時機・段階は学習する
- **聖水を使う条件**
- **カード固有の対象の選び方**（`effects.js` の各カードの選び方。`burnKillThreat` で顔か倒すかの基準だけは動く）
- **デッキの中身**。カードの入れ替えは学習しない

学習で伸びないデッキが「遊び込んでも伸びない」のか「つまみに無い判断で伸びる」のかは、この結果だけでは区別できない。

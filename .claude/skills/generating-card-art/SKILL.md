# カードイラスト自動生成

`デッキ/*.md` を読んでカードごとのプロンプトを組み立て、画像APIで生成する。
外部パッケージは使わない（Node標準のみ）。`npm install` は不要。

**このスキルが作るのはイラストだけ。** カード枠と数字の合成は `カードフレーム/` を使う別工程。

## 構成

| 場所 | 中身 |
|---|---|
| `art/decks.js` | `デッキ/*.md` のパーサ |
| `art/style.json` | **絵柄・構図・クラス別トーン・除外。画風を変えるならここ。英文と和訳が対** |
| `art/style.js` | style.json の読み出しだけ |
| `art/subjects.js` | **カードごとの被写体と人物の外見定義。絵の中身を変えるならここ。en と jp が対** |
| `art/prompt.js` | 上2つを合成してプロンプトを作る |
| `art/image.js` `art/providers/` | 画像APIの呼び出し（google / openai） |
| `art/review.js` | **和訳と英文の突き合わせ。生成前に必ず通す** |
| `art/list.js` / `art/generate.js` | 実行スクリプト |
| [reference/prompt-design.md](reference/prompt-design.md) | プロンプトの設計方針と、破綻したときの直し方 |

出力は `イラスト/<デッキ名>/<カード名>.png` と、同名の `.json`（カード情報＋使ったプロンプト）。

## 実行環境

**コマンドはプロジェクトルートから、パスはスラッシュ区切りで実行する。**

このプロジェクトのパスには日本語が含まれる。**Node.js v23.5.0 は日本語を含むパスのスクリプトを実行できず、
何も出力せず終了コード5（bashでは Segmentation fault）で落ちる。** その場合は v22 系を指定する。

```bash
# まずこれで試す
node .claude/skills/generating-card-art/art/list.js

# 無出力で落ちたら、日本語パスを扱えるnodeで実行する（v22.16.0で動作確認済み）
"C:/Users/beron/scoop/apps/nvm/current/nodejs/nodejs/node.exe" .claude/skills/generating-card-art/art/list.js
```

以降のコマンド例では `node` と書く。落ちたら上のフルパスに置き換える。

### APIキー

既定は Google。`GEMINI_API_KEY` を環境変数か、プロジェクトルートの `.env` に置く（`.env` は `.gitignore` 済み）。

```
GEMINI_API_KEY=...
```

OpenAI を使うときは `--provider openai` と `OPENAI_API_KEY`。

**キーが無いなら生成を実行せず、ユーザーに設定を頼む。** キーの中身を出力やコミットに出さない。

### モデルと費用

45枚を1周する費用が大きく変わる。**回す前にどのモデルで行くかユーザーに確認する。**

| モデル | 指定 | 目安 |
|---|---|---|
| `gemini-2.5-flash-image` | 既定 | 指示追従が良い。既定はこれ |
| `imagen-4.0-fast-generate-001` | `--model imagen-4.0-fast-generate-001 --aspect 3:4` | いちばん安い。縦横比に4:5が無い |
| `gpt-image-1` | `--provider openai` | 最も高い |

## コマンド

| コマンド | 用途 |
|---|---|
| `node …/art/list.js [デッキ…]` | 対象カードと生成済み状況の一覧。**APIを呼ばない** |
| `node …/art/list.js --card カード名` | そのカードの完成プロンプト（英文）を表示する |
| `node …/art/review.js [デッキ…]` | **和訳と英文を並べて表示。APIを呼ばない** |
| `node …/art/generate.js [デッキ…]` | 未生成のカードを生成する |

デッキ名を省略すると全デッキが対象。生成済みの画像は既定でスキップされる。

### オプション

| オプション | 既定 | 意味 |
|---|---|---|
| `--card <名前>` | — | そのカードだけ。複数回指定できる |
| `--force` | off | 生成済みでも上書きする |
| `--dry-run` | off | 生成せず対象だけ出す |
| `--no-leader` | off | リーダーの絵を対象から外す |
| `--provider <名>` | `google` | `google` / `openai` |
| `--model <名>` | プロバイダ既定 | モデルを差し替える |
| `--aspect <比>` | 種類ごと | 既定はリーダー `1:1` / キャラクター・スペル `4:5`。指定すると全カードその比になる |
| `--style <名前>` | style.json の `preset` | 絵柄のプリセット。`anime` / `oil` / `watercolor` |
| `--quality <質>` | `high` | OpenAIのときだけ効く |
| `--concurrency <n>` | `2` | 同時リクエスト数。429が出るなら下げる |
| `--out <dir>` | `イラスト` | 出力先ディレクトリ |

## カード枠との関係

`カードフレーム/frame.json` に枠の実測値がある。カード枠は種類ごとに
`カードフレーム/キャラクター/` `カードフレーム/スペル/` `カードフレーム/リーダー/` に分かれている。イラストに関係するのは次の2点。

- **アート窓の縦横比は種類で違う。** キャラクター0.84／スペル0.82／**リーダー0.93**。
  これに合わせて `style.json` の `aspect` が生成比を決めている（リーダーだけ `1:1`、他は `4:5`）
- **枠はイラストの上に文字を重ねない。** カード名・効果・コスト・攻撃力・HPは枠側の専用欄に入る

このため `style.json` の `frameSafe` は「外周5%に重要なものを置かない」だけを課している。
**枠が増えたり差し替わったら `frame.json` を測り直し、`aspect` を合わせる。**
**枠のためにイラスト内へ余白を作らせない。** 窓いっぱいに描かせる。

## 進め方

以下のチェックリストを応答にコピーし、完了したステップにチェックを入れながら進める。

```
イラスト生成の進捗:
- [ ] Step1. 対象を確認する
- [ ] Step2. プロンプトを詰める
- [ ] Step3. 和訳と英文を突き合わせ、ユーザーの承認を取る
- [ ] Step4. 1枚だけ試す
- [ ] Step5. まとめて生成する
- [ ] Step6. 結果を確認して手直しする
```

---

## Step1. 対象を確認する

```bash
node .claude/skills/generating-card-art/art/list.js
```

`subjects.js に定義が無い` と出たカードは、名前と効果から機械的に作った汎用プロンプトになる。
**絵の質が明確に落ちるので、生成前に Step2 で `subjects.js` に書く。**

## Step2. プロンプトを詰める

触るファイルは基本この2つ。方針は
**[reference/prompt-design.md](reference/prompt-design.md)** に書いてある。

- `art/style.json` — 画風・構図・クラス別の色・除外。**全カードに一律で効く**
- `art/subjects.js` — カードごとの被写体。**そのカードだけに効く**

**どちらも英文（`en`）と和訳（`jp` / `和訳`）が対になっている。**
APIへ送られるのは英文で、ユーザーが読むのは和訳。**片方だけ直さない。**

同じ人物が複数のカードに出るとき（ヴァルザ、ベルゼなど）は、
`CHARACTERS` に外見を1か所だけ書き、各カードから `character:` で参照する。
**外見をカードごとに書き直すと絵が別人になる。**

被写体は `バックエンドストーリー/` の設定から起こす。**推測で人物像を足さない。**

```bash
# 出来上がるプロンプトを目で確かめる
node .claude/skills/generating-card-art/art/list.js --card 師ベルゼ
```

## Step3. 和訳と英文を突き合わせる

**課金する前に、ここでユーザーに確認を取る。** 英文はそのままAPIへ送られるが、
ユーザーが読むのは和訳なので、**両者がずれていると意図と違う絵に金を払うことになる。**

```bash
node .claude/skills/generating-card-art/art/review.js --card ドロテ
node .claude/skills/generating-card-art/art/review.js アグロリーゼ > review.txt
```

被写体・構図・色と舞台・画風・除外の5区画を、和文と英文を並べて出す。次を確認する。

- **和訳が英文の内容を正しく表しているか。** 片方だけ直して放置していないか
- 被写体がカードの効果とキャラクター設定に合っているか
- `subjects.js に定義が無い` と出ているカードが残っていないか

**ずれていたら直すのは英文のほう。** ユーザーが和訳の言葉で意図を述べたなら、
その意図に英文を合わせ、和訳も最終形に揃える。**必ず両方を更新する。**

**ユーザーの承認を得てから Step4 へ進む。**

## Step4. 1枚だけ試す

**いきなり全部回さない。** 45枚あるので、方向性がずれていると費用も時間も無駄になる。

```bash
node .claude/skills/generating-card-art/art/generate.js --card 師ベルゼ
```

出た画像を見て、画風と、窓いっぱいに描けているかを確認する。ずれていれば Step2 に戻る。
採用済みの絵を壊さずに試すなら `--out イラスト_試作` に逃がす。
**ユーザーに画風の合否を確認してから Step5 へ進む。**

## Step5. まとめて生成する

```bash
node .claude/skills/generating-card-art/art/generate.js アグロリーゼ
node .claude/skills/generating-card-art/art/generate.js
```

デッキ単位で区切って回す。失敗したカードは最後にまとめて出るので、そのカードだけ再実行する。
**生成済みはスキップされるので、同じコマンドを再実行すれば失敗分だけ埋まる。**

## Step6. 結果を確認して手直しする

生成物を見て、以下を確認する。

- 文字・数字・枠が写り込んでいないか（画像生成が最も失敗しやすい箇所）
- 同一人物のカード同士で顔と服装が揃っているか
- 被写体が中央に小さく浮いていないか（窓いっぱいに描けているか）

直したい1枚だけ引き直す。

```bash
node .claude/skills/generating-card-art/art/generate.js --card ポルカ --force
```

## 注意事項

このスキルでやってほしくないこと。

- **確認なしに全カードを一括生成しない。** 1枚試して画風とモデルの合意を取ってから回す
- **review.js の突き合わせ（Step3）を飛ばして生成しない。** 意図と違う絵に課金することになる
- **英文だけ直して和訳を放置しない。** 対訳が崩れると次から確認できなくなる
- **`--force` で既存画像を無断で上書きしない。** ユーザーが採用した絵が消える
- **`デッキ/*.md` や `バックエンドストーリー/*.md` を絵の都合で書き換えない。** 設定が正で、プロンプト側を合わせる
- **人物の外見を `subjects.js` のカード側に直接書かない。** `CHARACTERS` に集約する。別人になる
- **APIキーを出力・コミット・プロンプトに含めない**
- **生成に失敗したカードを黙って飛ばさない。** 失敗一覧をユーザーに伝える
- **画像に文字を描かせようとしない。** コスト・攻撃力・HP・カード名・効果は枠側の欄に入る

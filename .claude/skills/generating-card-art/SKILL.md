# カードイラスト自動生成

カードのmdに書かれた**日本語**を繋いでプロンプトを組み立て、送る直前に英訳して画像APIへ渡す。
外部パッケージは使わない（Node標準のみ）。`npm install` は不要。

**このスキルが作るのはイラストだけ。** カード枠と数字の合成は `カードフレーム/` を使う別工程。

## 絵の指定はどこにあるか

**プロンプトはコードの中には無い。全部mdに書いてある。**効く範囲で3階層に分かれている。

| 範囲 | 場所 | 中身 |
|---|---|---|
| 全カード共通 | `イラスト/共通ルール.md` | 絵柄（アニメ／油彩／水彩）、構図、画面の使い方、描かせないもの |
| デッキごと | `デッキ/<デッキ名>/overview.md` の「見た目の共通ルール」 | 光源と配色、力の見た目、明暗の振り分け、人物の描き分け |
| カード1枚ごと | `デッキ/<デッキ名>/カード一覧/*.md` の `## 絵` | 外見・情景・背景 |

**直す前に、どの範囲の問題なのかを決める。**
1枚だけおかしいならカードmd、同じデッキが全部おかしいなら overview.md、
全デッキおかしいなら 共通ルール.md。

## 構成

| 場所 | 中身 |
|---|---|
| `システム/` | **共有コア。**デッキとカードmdのパーサ、共通ルールのパーサ、プロンプトの組み立て、縦横比。`showing-card-prompt` も同じものを使う |
| `art/translate.js` | 日本語→英語。訳した英文はキャッシュされる |
| `art/image.js` `art/providers/` | 画像APIの呼び出し（google / openai） |
| `art/list.js` / `art/review.js` / `art/generate.js` | 実行スクリプト |
| [reference/prompt-design.md](reference/prompt-design.md) | 絵が破綻したときの直し方 |

出力は `イラスト/<デッキ名>/<カード名>.png` と、同名の `.json`（カード情報・日本語プロンプト・送った英文）。

### 英文はファイルに書かない

**カードmdに英語を書かない。**送信直前に `gemini-flash-latest` が英訳する。

訳した英文は `.json` に保存され、**日本語が変わっていなければ次回もその英文を使い回す。**
だから同じmdからは必ず同じ絵が出る。訳し直すと絵が変わってしまうため。

## 実行環境

**コマンドはプロジェクトルートから、パスはスラッシュ区切りで実行する。**

このプロジェクトのパスには日本語が含まれる。**Node.js v23.5.0 は日本語を含むパスのスクリプトを実行できず、
何も出力せず終了コード5（bashでは Segmentation fault）で落ちる。** その場合は v22 系を指定する。

```bash
# まずこれで試す
node .claude/skills/generating-card-art/art/list.js

# 無出力で落ちたら、日本語パスを扱えるnodeで実行する（v22.16.0で動作確認済み）
"C:/Users/beron/scoop/apps/nvm/current/nodejs/nodejs/node.exe" .claude/skills/generating-card-art/art/list.js
```

以降のコマンド例では `node` と書く。落ちたら上のフルパスに置き換える。

### APIキー

既定は Google。`GEMINI_API_KEY` を環境変数か、プロジェクトルートの `.env` に置く（`.env` は `.gitignore` 済み）。
画像生成と翻訳の両方で同じキーを使う。

```
GEMINI_API_KEY=...
```

OpenAI を使うときは `--provider openai` と `OPENAI_API_KEY`（翻訳は Google のまま）。

**キーが無いなら生成を実行せず、ユーザーに設定を頼む。** キーの中身を出力やコミットに出さない。

### モデルと費用

45枚を1周する費用が大きく変わる。**回す前にどのモデルで行くかユーザーに確認する。**

| モデル | 指定 | 目安 |
|---|---|---|
| `gemini-3-pro-image` | 既定 | Nano Banana Pro。描き込みと指示追従が最も良い。2K出力 |
| `gemini-3.1-flash-image` | `--model gemini-3.1-flash-image` | 安い。方向性を探る段階向き |
| `gpt-image-1` | `--provider openai` | 最も高い |

**キャラの方向性が決まっていない段階で本番モデルを使わない。**
安いモデルで当たりを付けてから Pro で引き直すほうが、結果的に安く済む。

## コマンド

| コマンド | 用途 |
|---|---|
| `node …/art/list.js [デッキ…]` | 対象カードと生成済み状況の一覧。**APIを呼ばない** |
| `node …/art/list.js --card カード名` | そのカードの完成プロンプト（日本語）を表示する |
| `node …/art/review.js [デッキ…]` | **プロンプトを区画ごとに表示。APIを呼ばない** |
| `node …/art/generate.js [デッキ…]` | 未生成のカードを生成する |

デッキ名を省略すると全デッキが対象。生成済みの画像は既定でスキップされる。

### オプション

| オプション | 既定 | 意味 |
|---|---|---|
| `--card <名前>` | — | そのカードだけ。複数回指定できる |
| `--force` | off | 生成済みでも上書きする |
| `--dry-run` | off | 生成せず対象だけ出す |
| `--no-leader` | off | リーダーの絵を対象から外す |
| `--provider <名>` | `google` | `google` / `openai` |
| `--model <名>` | プロバイダ既定 | モデルを差し替える |
| `--aspect <比>` | 種類ごと | 既定は全種類 `4:5`。指定すると全カードその比になる |
| `--style <名前>` | 共通ルール.md の（既定） | 絵柄。`アニメ` / `油彩` / `水彩` |
| `--quality <質>` | `high` | OpenAIのときだけ効く |
| `--concurrency <n>` | `2` | 同時リクエスト数。429が出るなら下げる |
| `--out <dir>` | `イラスト` | 出力先ディレクトリ |

## カード枠との関係

`カードフレーム/frame.json` に枠の実測値がある。イラストに関係するのは次の2点。

- **生成比は全種類 `4:5`。** `art/targets.js` の `ASPECT` にある。**枠を差し替えたら `frame.json` を測り直して合わせる**
- **絵の下4分の1は効果テキストの帯に隠れる。** そこに顔や主役を置かない

**この「帯に隠れる」をプロンプトに書くとモデルが帯そのものを描く。**
`共通ルール.md` では「顔や主役を置かず静かな背景にする」と書き、帯を描かせない指示を添えている。**この書き方を崩さない。**

## 合成まで通す

イラストができたら、カード枠と合成して完成カードにする。

```bash
powershell -ExecutionPolicy Bypass -File "カードフレーム/tools/compose.ps1" -Deck "デッキ名" -Force
```

合成は `イラスト/<デッキ名>/<カード名>.json` のカード情報を読む。
**新しいクラスを作ったら `frame.json` の `frames` にクラス名と枠画像を追加する。**無いと合成に失敗する。

## 進め方

以下のチェックリストを応答にコピーし、完了したステップにチェックを入れながら進める。

```
イラスト生成の進捗:
- [ ] Step1. 対象を確認する
- [ ] Step2. プロンプトを詰める
- [ ] Step3. プロンプトを見せて承認を取る
- [ ] Step4. 1枚だけ試す
- [ ] Step5. まとめて生成する
- [ ] Step6. 結果を確認して手直しする
```

---

## Step1. 対象を確認する

```bash
node .claude/skills/generating-card-art/art/list.js
```

`カードmdの 外見／情景 が空` と出たカードは、絵の指定が書かれていない。
**Step2 でカードmdに書く。**

## Step2. プロンプトを詰める

触るのは3つのmdだけ。方針は
**[reference/prompt-design.md](reference/prompt-design.md)** に書いてある。

- `イラスト/共通ルール.md` — 絵柄・構図・除外。**全デッキに効く**
- `デッキ/<デッキ名>/overview.md` の見た目の共通ルール — **そのデッキ全部に効く**
- `デッキ/<デッキ名>/カード一覧/*.md` の `## 絵` — **そのカードだけに効く**

**すべて日本語で書く。英語を書かない。**

```bash
# 出来上がるプロンプトを目で確かめる
node .claude/skills/generating-card-art/art/list.js --card 師ベルゼ
```

絵の指定は `バックエンドストーリー/` の設定から起こす。**推測で人物像を足さない。**

## Step3. プロンプトを見せて承認を取る

**課金する前に、ここでユーザーに確認を取る。**

```bash
node .claude/skills/generating-card-art/art/review.js --card ドロテ
node .claude/skills/generating-card-art/art/review.js アグロリーゼ > review.txt
```

区画ごとに分けて出るので、次を確認する。

- 外見・情景・背景がカードの効果とキャラクター設定に合っているか
- 同じ人物が出る他のカードと、外見の記述が一致しているか
- 絵の指定が空のカードが残っていないか

**ユーザーの承認を得てから Step4 へ進む。**

## Step4. 1枚だけ試す

**いきなり全部回さない。** 45枚あるので、方向性がずれていると費用も時間も無駄になる。

```bash
node .claude/skills/generating-card-art/art/generate.js --card 師ベルゼ
```

出た画像を見て、画風と、窓いっぱいに描けているかを確認する。ずれていれば Step2 に戻る。
採用済みの絵を壊さずに試すなら `--out イラスト_試作` に逃がす。
**ユーザーに画風の合否を確認してから Step5 へ進む。**

## Step5. まとめて生成する

```bash
node .claude/skills/generating-card-art/art/generate.js アグロリーゼ
```

デッキ単位で区切って回す。失敗したカードは最後にまとめて出るので、そのカードだけ再実行する。
**生成済みはスキップされるので、同じコマンドを再実行すれば失敗分だけ埋まる。**

## Step6. 結果を確認して手直しする

**生成物を必ず全部見る。**次の失敗が実際に起きている。

- **文字が描き込まれていないか** — プロンプトの一部が画面に文字として出る
- **白い縁や帯が付いていないか** — 絵の外側の要素を絵の中に描いてしまう
- 同一人物のカード同士で顔と服装が揃っているか
- 被写体が中央に小さく浮いていないか
- 立っているものが接地して見えるか

直したい1枚だけ引き直す。

```bash
node .claude/skills/generating-card-art/art/generate.js --card ポルカ --force
```

## 注意事項

このスキルでやってほしくないこと。

- **確認なしに全カードを一括生成しない。** 1枚試して画風とモデルの合意を取ってから回す
- **review.js（Step3）を飛ばして生成しない。** 意図と違う絵に課金することになる
- **カードmdに英語を書かない。** 英訳は送信直前にシステムが行う
- **`--force` で既存画像を無断で上書きしない。** ユーザーが採用した絵が消える
- **`デッキ/` や `バックエンドストーリー/` を絵の都合で書き換えない。** 設定が正で、プロンプト側を合わせる
- **ユーザーが書いた 外見／情景／背景 を、勝手に書き換えない。** 直すなら理由を言って合意を取る
- **ユーザーが設定した値を「間違い」として直さない。** 測った数字と食い違ったら、直す前に言う
- **既存ファイルを丸ごと上書きしない。** 必ず読んでから、変更点だけ当てる
- **APIキーを出力・コミット・プロンプトに含めない**
- **生成に失敗したカードを黙って飛ばさない。** 失敗一覧をユーザーに伝える
- **画像に文字を描かせようとしない。** コスト・攻撃力・HP・カード名・効果は枠側の欄に入る
- **生成した画像を見ずに完了と報告しない。** 文字混入と白縁は目で見ないと分からない
